## POST 2 — The Footwear Manufacturer (Post in 2-3 days)

I'm embedded on-staff at a regional manufacturer right now, and I'm building something I've never seen anyone else build.

Phase 1 was full-stack automation: 15+ Docker containers, n8n workflows handling order processing, customer communications, inventory monitoring, and supply chain tracking. Every LLM runs on their hardware. Every byte stays inside their network. Manual processing down ~70%.

Phase 2 is where it gets interesting. I'm building an autonomous IT support agent that doesn't just advise — it acts.

Here's the workflow:
1. Ticket lands in Jira
2. Agent triages it — category, urgency, complexity
3. Agent analyzes the issue and guides the technician toward first-call resolution
4. If it's a known issue with a proven fix, the agent drafts a scripted fix
5. Human technician reviews and approves (human-in-the-middle, always)
6. Agent sends the fix directly to the machine via MDM — Windows, Linux, Android
7. Agent writes the SOP documenting the entire resolution
8. Ticket closed with full institutional knowledge captured

This isn't a chatbot. It's an operational agent that diagnoses, fixes with human approval, and documents — automatically. Every resolved ticket makes the system smarter. Every SOP becomes institutional memory.

The agent runs on Hermes Agent framework, integrated with Jira, the MDM platform, and their full device fleet. Local-first. Zero cloud dependency.

Phase 3 (planned): extending this into an autonomous SOC. Elastic Stack as the SIEM. pfSense wired in so the AI can read traffic flows and — with human approval — modify firewall rules to block threats in real time. Endpoint agents on every machine that can isolate compromised systems, kill malicious processes, and quarantine files. Every detected threat becomes a new detection rule. Every remediation becomes an SOP. The security posture compounds — without hiring a SOC team.

Phase 4 (planned): proactive printer fleet monitoring. The agent tracks toner levels, paper supply, paper jams, connectivity, queue backups, and firmware status across every printer. Predicts failures before they happen. Auto-creates Jira tickets with diagnostics before anyone picks up the phone. Common issues (stuck spooler, network drift, driver mismatch) get auto-remediated with human approval. Nobody calls help desk to say "the printer works great." They call when it's broken and frustrated. The agent knows it's dying before they do.

Phase 1: Automation. Phase 2: Autonomous IT operations. Phase 3: Autonomous security operations. Phase 4: Proactive infrastructure. Phase 5: AI-powered ERP tooling — natural language interfaces on top of the legacy GCS A2000 ERP system, intelligent data entry, automated reporting, and workflow automation. The ERP stays intact. The AI sits between the user and the system, translating intent into action.

Five phases. One company. One operator. Building the entire AI operations stack from the inside.

This is what AI infrastructure looks like when you build it from the inside. Not a chatbot. Not a SaaS subscription. An operational architecture that diagnoses, fixes, secures, and documents — with humans in control, machines doing the work.

The tools are free. The expertise to turn them into production infrastructure is not.
